## 1. 目标

保证「本地提醒」在真实国内机型上可交付，而不是只在模拟器/原生 Android 上可用。本表是内测与设置页引导的需求源。

---

## 2. 通知渠道（与 PRD 一致）

| channelId | 名称 | 重要性 | 用途 | 附加行为 |
|-----------|------|--------|------|----------|
| `event_reminder` | 日程提醒 | HIGH | 课程/日程开始前 | 点通知进 Event/课程详情 |
| `todo_due` | 待办截止 | DEFAULT | 截止前 | 点进 Todo 详情；可提供「完成」动作 |
| `agent_result` | Agent 结果 | LOW | 可选；后台长结果 | MVP 可不做 |

**规则**

- minSdk 26：创建渠道后才能发通知
- 渠道删除重建会丢用户偏好 → 渠道 id 稳定，名称可 i18n
- 每条通知需 `contentIntent` 可进 App 对应页面

## 3. 权限与闹钟状态机

```text
[App 安装]
    │
    ▼
[未请求 POST_NOTIFICATIONS] (A13+)
    │ 用户设置提醒 / 首次进通知相关
    ▼
[已请求]
    ├─ 拒绝 → 设置页红点引导；仍可建提醒但无法展示
    └─ 允许 → [检查精确闹钟 A12+]
                ├─ 可用 → scheduleExact
                └─ 不可用 → 尝试申请 SCHEDULE_EXACT_ALARM
                    ├─ 允许 → scheduleExact
                    └─ 拒绝 → setAndAllowWhileIdle / inexact
                         + 设置页提示「提醒可能不准时」
```

| API | 用途 | 备注 |
|-----|------|------|
| POST_NOTIFICATIONS | 展示通知 | Android 13+ |
| SCHEDULE_EXACT_ALARM | 精确触发 | Android 12+；14+ 更严 |
| USE_EXACT_ALARM | 特定类型应用 | 日历类可评估；商店政策需核对 |

**MVP 策略**：优先精确；失败降级不精确 + 明示用户，不阻塞保存。

## 4. 调度规则

| 场景 | 做法 |
|------|------|
| reminderOffsets 相对 startAt/dueAt | 计算 trigger = 事件时刻 - offset |
| trigger 已过去 | 不调度或立即「已错过」策略（MVP：跳过并在详情标未提醒） |
| 重复事件 | MVP：为未来有限窗口（如 30 天）预排；或 Alarm 到期再排下一次 |
| App 更新/重启 | BOOT_COMPLETED 或 WorkManager 补排（注意国内部分机型限制） |
| 数据库改期/删除 | 必须取消/重排对应 PendingIntent（id 用实体 id+offset） |

## 5. 通用内测验收现象

| # | 检查项 | 通过现象 |
|---|--------|----------|
| G1 | 渠道存在 | 系统通知设置里能看到三个渠道（至少两个必做） |
| G2 | 通知权限 | 允许后，到点弹出横幅/状态栏 |
| G3 | 精确时间 | 目标时间 ±1 分钟内展示（精确闹钟已开） |
| G4 | 点按跳转 | 进入正确详情页 |
| G5 | 删除后不再提醒 | 软删后到点无通知 |
| G6 | 改期后按新时间 | 取消旧闹钟并重排 |
| G7 | 关进程 | 杀进程后仍能提醒（在厂商白名单满足时） |
| G8 | 重启手机 | 仍能提醒（若实现了补排） |

## 6. 厂商检查表（MVP 内测范围）

> 路径名称随系统版本变化，内测时以真机为准；下表为引导文案草稿与验收现象。

| 项 | 引导动作 | 验收 |

## 8. 设置页映射（对接 D5 `settings_notify_oem`）

| 检查项 | UI 控件 |
|--------|---------|
| POST_NOTIFICATIONS | 状态行 + 去开启 |
| SCHEDULE_EXACT_ALARM | 状态行 + 去设置 |
| OEM 项 | 检测品牌 → 显示步骤 → 「我已设置 / 重新检测」 |
| 复检 | 刷新权限状态（无法完美检测 OEM 全部项时，以「用户已确认」兜底） |

**检测边界**：系统权限可查；部分 OEM 自启动无法 API 检测 → 引导以用户确认 + 推送测试通知按钮为主。

---

## 9. 提供「测试提醒」按钮

设置页提供：

- 「发送测试通知（现在）」：验证渠道与权限，不依赖 Alarm
- 「调度 10 秒后的测试提醒」：验证 Alarm 路径

内测用例依赖此按钮，避免每次等真实课点。
