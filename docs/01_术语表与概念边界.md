## 3. 概念边界（必须能答对）

### 3.1 Event vs Todo

| 判断点 | Event | Todo |
|--------|-------|------|
| 是否占用时间块 | 是（可有全天） | 否（只有可选截止时刻） |
| 是否有完成态 | 无 | 有 `isDone` |
| 典型用户语言 | 「明天下午三点开会」 | 「周五前交实验报告」 |

**规则**：用户说「安排/会议/上课/占用时间」→ Event；说「要做完/交/别忘了」→ Todo。同一句话两个意图时，Agent 应拆成两条或反问。

### 3.2 Course vs Event

| 判断点 | Course | Event |
|--------|--------|-------|
| 是否由学期/周次生成 | 是 | 否 |
| 是否可改「某一周」定义 | 否（改定义即改系列） | 系列可只改本次 |
| 在日历上 | 投影只读 | 可编辑 |

**规则**：用户要「加高数课」→ `create_course`；要「下周三调到教室 B」→ 不改 Course，新建 Event（MVP）。

### 3.3 Course vs Course Occurrence

- **Course**：可编辑的定义行（D3）。
- **Course Occurrence**：某日 Agenda 上的一次课，由 `(Course, 教学周, weekday)` 计算得到。
- **禁止**：把 Occurrence 当可写实体；`update_course` 改的是定义，会影响所有匹配周次。

### 3.4 删除：定义 vs 本次 vs 系列

| 操作 | MVP 行为 |
|------|----------|
| 删除 Event（无重复） | 软删该条 |
| 删除 Event 本次（有重复） | 仅跳过/删除该日期实例（实现可用例外或删除记录，见 D2） |
| 删除 Event 整个系列 | MVP **不提供**工具级「删系列」；用户需改规则或手动处理（可进 V1.1） |
| 删除 Course | 软删课程定义，之后不再投影 |
| 删除 Todo | 软删 |

### 3.5 「今天」与教学周

- **今天** = 设备本地日（设置时区变更不影响已存绝对时间戳）。
- **第 N 教学周** = 从 `week1Monday` 起算的第 N 个自然周；与「本周日历周」可能不同（学期未开学时教学周可为 0 或无效）。
- 周课表默认显示「当前教学周」；无学期时显示空态。

## 4. 写法约定

| 约定 | 说明 |
|------|------|
| 中文规范用语优先 | 正文、UI 文案、线框标注用规范用语 |
| 英文 ID | 数据字段、工具名、错误码用英文，见 D3/D4 |
| 用户可见模糊时间 | 仅出现在对话气泡；进入确认卡后必须绝对时间 |
| 「删除」 | 默认指软删除；文档中写「硬删」才表示物理删除（MVP 不做） |
| 「本地」 | 一律指设备本地存储与本地时区，除非写明「云端」 |

## 5. 边界自检题（评审用，答案在下）

1. 用户说「把周三的高数改到图书馆」——改的是 Course 还是 Event？  
2. 「删掉今天所有待办」是低风险还是高风险？  
3. 课程实例能不能直接编辑地点？  
4. 「明天下午」能否原样显示在确认卡？  
5. 某日 Agenda 从哪些数据来源合成？

**答案**：

1. MVP：优先新建/修改调课 Event，或反问；不直接改 Course 除非用户明确说「以后都改」。  
2. 高风险（批量删除）→ 二次确认。  
3. 不能；改定义用 `update_course`，或建额外 Event。  
4. 不能；必须绝对时间。  
5. Event + Course Occurrence + Todo（列表区）。
