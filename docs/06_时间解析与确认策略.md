## 1. 目标

把中文口语中的时间表达，稳定映射为 **设备本地绝对时间**，并在写操作前用确认卡钉死。解析不确定时必须反问，禁止静默猜一个时间写库。

---

## 2. 解析流水线（逻辑）

```text
用户原文
  → 意图分类（只读查询 / 创建 / 修改 / 删除 / 闲聊拒绝）
  → 抽取时间短语 + 实体（标题线索、课程名、待办）
  → 时间解析器（白名单规则 + 模型填充）
  → 结构化时间槽：
      { kind, localDateTime | localDate | timeOnly, confidence, raw }
  → 槽位完整性检查
      缺日期/缺钟点/冲突 → ClarifyQuestion
      完整且 confidence 高 → 允许进入工具参数
  → 工具调用（D4）→ 确认卡展示绝对时间（中高风险或创建后撤销窗）
```

**分工建议**

| 步骤 | 端上规则 | 模型 |
|------|----------|------|
| 相对日词、周X、N点、上下午 | 可确定性解析 | 可辅助 |
| 「大后天晚上」「下下周」等 | 规则表覆盖 | 边界用例交模型 |
| 非时间槽填充（标题/地点） | 校验长度 | 主导 |

MVP 允许模型输出已解析的 ISO 时间；端上必须再做一次「是否合法、是否在合理窗口」校验。

## 3. 时间表达白名单（MVP 必须支持）

### 3.1 相对日

| 表达（示例） | 含义 |
|--------------|------|
| 今天 / 今晚 / 今早 | 本地今日 |
| 明天 / 明早 / 明晚 / 明天早上/中午/下午/晚上 | 本地今日 +1 日 |
| 后天 | +2 日 |
| 大后天 | +3 日 |
| 昨天 | -1 日（仅查询/改错场景） |
| 周X / 星期X / 礼拜X | 下一个即将到来的 X（含今天若「本周周X」语境） |
| 本/这周周X | 本周内该日；若已过则反问是否下周 |
| 下周 / 下下周 + 周X | +7 / +14 周对齐 |
| X月X日 / X月X号 | 绝对日期（今年；若已过且语境像将来 → 反问是否明年） |
| 号 / 日 结尾数字日期 | 同上 |

### 3.2 钟点与时段

| 表达 | 含义 |
|------|------|
| N点 / N:00 / N点半 / N:15 | 时刻 |
| 早上 / 上午 | 默认 08:00–11:59；无具体点时用 09:00 作建议值并进确认卡 |
| 中午 | 12:00 |
| 下午 | 13:00–17:59；无具体点建议 15:00 |
| 晚上 / 晚 | 18:00–21:59；无具体点建议 19:00 |
| 凌晨 | 00:00–05:59 |
| 点前后模糊（两三点） | 反问或取中间值并确认 |

### 3.3 组合示例（应能解析）

| 用户说 | 结果（假设今天 2026-08-11 周一） |
|--------|----------------------------------|
| 明天下午三点开会 | 2026-08-12 15:00 |
| 后天上午十点半实验 | 2026-08-13 10:30 |
| 周五有什么安排 | 查询 2026-08-15 全日 |
| 下周三第一节高数 | 课程类，走 create_course/list，不是 Event 钟点 |
| 今晚八点提醒我取快递 | Todo due 2026-08-11 20:00 |
| 8月20号上午九点面试 | 2026-08-20 09:00 |

## 4. 必须反问 / 不可静默写入

| 情况 | 策略 |
|------|------|
| 只有时段没有日（「下午开会」） | 反问今天还是明天 |
| 只有日没有钟点且非全天（「明天开会」） | 反问几点，或提议「全天」二选一 |
| 「尽快」「有空」「过几天」 | 反问具体日期 |
| 解析出两个互相矛盾时间 | 列出选项让用户点 |
| 「明天下午」用于**创建** | 可建议 15:00，但**确认卡必须显示绝对时间**；用户可改 |
| 跨年/历史日期用于将来事件 | 反问年份 |
| 删除指代不清（「删掉那个」）且列表有多个候选 | 反问或展示候选列表 |
| 表达不在白名单且模型 confidence 低 | 反问 |

**反问文案模板**

- 「你是要 **8月12日 15:00** 还是 **8月13日 15:00**？」
- 「「明天下午」我先按 **15:00** 理解，可以吗？」
- 「这件事没有具体时间，要设成 **全天** 还是定一个点？」

## 5. 时间槽结构（逻辑）

```json
{
  "raw": "明天下午三点",
  "kind": "datetime",
  "localDateTime": "2026-08-12T15:00:00",
  "confidence": "high",
  "needsConfirmAbsDisplay": true
}
```

| 字段 | 说明 |
|------|------|
| kind | `date` \| `datetime` \| `time_only` \| `range` \| `week` |
| localDateTime | 本地无 offset ISO |
| confidence | high / medium / low；low 禁止写库 |
| needsConfirmAbsDisplay | 创建类一律 true |

## 6. 与确认策略的组合

沿用 D4 风险矩阵，叠加时间规则：

| 操作 | 时间要求 | 确认卡 |
|------|----------|--------|
| list_* | 允许相对日，返回时用绝对日展示 | 无（列表头显示日期范围） |
| create_event / create_todo | 必须绝对时间或明确全天 | 创建后结果卡含绝对时间；若解析曾降级建议值，创建前可先 Confirm |
| update_* 改时间 | 显示 before → after 绝对时间 | 必有 diff |
| delete_* | 卡片显示该条绝对时间 | 必有 |
| 课程 | weekday + 教学周，不解析钟点为 Event | 确认卡显示「第 X 周 周三 第 a-b 节」 |

### 6.1 创建前何时强制 Confirm

虽 D4 写 create 为低风险，以下情况**升级为创建前 Confirm**：

1. 时间 confidence = medium
2. 使用了默认时段建议（下午→15:00）
3. 将创建重复规则
4. 同日程疑似与已有安排冲突（可只提示不阻断，但时间来自模糊解析时建议确认）

其余高置信创建仍可「直接执行 + 可撤销」。

## 7. 重复相关口语

| 表达 | 映射 |
|------|------|
| 每天 X 点 | DAILY |
| 每周X | WEEKLY |
| 每个工作日 / 工作日每天 | WORKDAYS |
| 每两周 / 单双周 | **反问**或引导课程工具；MVP Event 不支持 |
| 直到月底 / 到 X 日 | repeatUntil |
| 一共 N 次 | repeatCount |
| 只有「每天」无结束 | **反问**结束日或次数（防无限） |

---

## 8. 课程 vs 日程的分流

| 信号 | 倾向 |
|------|------|
| 课名 + 节次（「第3-4节」）+ 周次（「1-16周」） | Course |
| 「每周三都要上」 | Course |
| 「下周三调个会」 | Event |
| 「周三下午的课换个教室」且仅一次 | Event 调课例外表达 |
| 模型不确定 | 反问「这是以后每周都有的课，还是只这一次？」 |

---

## 9. 端上校验（写库前）

1. ISO 可解析
2. `endAt > startAt`（非全天）
3. 不在拒绝窗口：默认禁止 startAt < now - 1 年（历史事件仅允许明确「补记」语境，MVP 可简单禁止）
4. 重复必须有 until/count
5. confidence ≥ high，或已用户确认

失败 → `VALIDATION_ERROR` / 进入 Clarify。
